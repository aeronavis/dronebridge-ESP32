DroneBridge for ESP32 2.1.0 (LightX) - build instructions for ESP32-C61
=======================================================================

Branch ESP32-C61 = DroneBridge v2.1.0 (tag c05592d) + LightX changes (same as branch ESP32-C3)
+ ESP32-C61 port.

Toolchain (tested)
  ESP-IDF   : v5.5.6           - ESP32-C61 needs ESP-IDF 5.5 or newer
  Python    : 3.12 (3.12.10)   - ESP-IDF 5.5 does NOT support Python 3.14
  Compiler  : riscv32-esp-elf-gcc 14.2.0 (installed by ESP-IDF)
  CMake     : 3.30.2, Ninja 1.12.1 (installed by ESP-IDF)
  esptool   : 4.12.0 (installed by ESP-IDF)
  Node.js   : v26.7.0 with npm 11.19.0 - builds the web interface (www.bin)
  Git       : needed for the submodules and the ESP-IDF component manager (internet access on first build)

  Do NOT use ESP-IDF 6.x: mbedTLS 4 / cJSON / GCC 16 break DroneBridge 2.1.0.

Hardware (tested)
  ESP32-C61-DevKitC-1-N8R2, chip ESP32-C61 rev v1.0, 8 MB flash, 2 MB PSRAM
  UART to flight controller : TX = GPIO11, RX = GPIO10, 115200 baud, MAVLink
  Debug console             : native USB port (USB-Serial-JTAG, GPIO12/13), not UART0
  Reset button              : GPIO9 (BOOT)
  Never use GPIO14-21 (SPI flash/PSRAM bus on ESP32-C61)

Changes vs. branch ESP32-C3
  - main/idf_component.yml        : button ^4.1.3, esp-now ^2.5.3 (local copy), mdns ^1.11.3
  - components/esp-now            : esp-now 2.5.3 with C61 fixes (ROM header includes, Wi-Fi 6 rx field)
  - main/main.c                   : button 4.x API; C61 UART defaults GPIO11/10
  - main/db_esp_now.c             : include hal/aes_types.h (C61 has no AES hardware)
  - main/CMakeLists.txt           : -Wno-address-of-packed-member (fastmavlink headers)
  - sdkconfig / sdkconfig.defaults.esp32c61 : target esp32c61, console on USB-Serial-JTAG

1. Get the code (with submodules fastmavlink and pymavlink)
     git clone --recursive -b ESP32-C61 https://github.com/aeronavis/dronebridge-ESP32.git
   Already cloned without --recursive:
     git submodule update --init

2. Wi-Fi credentials (not in git)
   Copy main/db_credentials.h.example to main/db_credentials.h and set
   DB_DEFAULT_WIFI_SSID and DB_DEFAULT_WIFI_PWD.
   Without this file the build warns and uses the DroneBridge defaults
   ("DroneBridge for ESP32" / "dronebridge").

3. Build (PowerShell, ESP-IDF 5.5.6 environment active, Python 3.12 on PATH)
     cd dronebridge-ESP32
     idf.py build
   The committed sdkconfig is already set for esp32c61. Only after deleting sdkconfig:
     idf.py set-target esp32c61

4. Flash (dev kit "UART" USB-C port, nothing connected to GPIO10/11; 2 MB layout, DIO, 80 MHz)
   First flash / coming from another firmware: erase first
     python -m esptool --chip esp32c61 -p COMx erase_flash
     python -m esptool --chip esp32c61 -p COMx -b 460800 --before default_reset --after hard_reset write_flash --flash_mode dio --flash_size 2MB --flash_freq 80m 0x0 build\bootloader\bootloader.bin 0x8000 build\partition_table\partition-table.bin 0x10000 build\db_esp32.bin 0x190000 build\www.bin
   If the chip does not enter download mode by itself: hold BOOT, press RESET, release BOOT.

After flashing
  - Logs: dev kit "USB" port (USB-Serial-JTAG), 115200
  - Wi-Fi station mode with the credentials from main/db_credentials.h. The UART to the
    flight controller only starts AFTER Wi-Fi is connected.
  - Skybrush support (UDP 14555) enabled
  - BOOT button (GPIO9): short press = station mode with default credentials,
    long press = reset Wi-Fi mode, SSID and password, then reboot
  - At power-up the C61 ROM prints a few boot lines on UART0 (GPIO11); harmless for ArduPilot.
  - Do not use the "UART" USB port and the flight controller on GPIO10/11 at the same time.

Notes
  - Flashing does not burn eFuses (secure boot and flash encryption are off). Never run espefuse.
